### Should fix

- **[.claude/settings.json:33-36]** Removing `Read(./**/.env.*)` and `Edit(./**/.env.*)` also lets Claude read `.env.local`, `.env.production` and similar secret files, not just `server/.env.example`. Deny rules beat allow rules, so an allow exception can't narrow it. **Fix (owner's call):**
  - Restore both deny rules and rename the template to `server/example.env`, updating `.gitignore` and the references; or
  - keep the name and replace the broad rule with explicit denies (`.env.local`, `.env.*.local`, `.env.prod*`, `.env.dev*`, `.env.test*`, `.env.stag*`).

  *(This was the owner's own change; the audit doesn't edit permission settings.)*
- **[server/src/dropshare_server/core/db.py:21]** `create_engine` lacks `hide_parameters=True`. SQLAlchemy errors include bound values, which get logged through `logger.exception` and `exc_info`. From M2 these values include password and token hashes and emails (NFR-OPS-01). **Fix:** add `hide_parameters=True` and a test.
- **[server/src/dropshare_server/core/error_handlers.py:44]** Any `HTTPException` other than 404/405 becomes `INTERNAL_ERROR` with a 4xx status, for example `401 INTERNAL_ERROR`. That breaks the client's planned handling of `UNAUTHENTICATED` and `RATE_LIMITED`. The handler also drops `exc.headers` (`Allow`, `WWW-Authenticate`). **Fix:** map 400 → `VALIDATION_ERROR`, 401 → `UNAUTHENTICATED`, 403 → `FORBIDDEN`, 413 → `FILE_TOO_LARGE`, 429 → `RATE_LIMITED`, 503 → `SERVICE_UNAVAILABLE`, ≥500 → `INTERNAL_ERROR`; pass the headers through.
- **[server/src/dropshare_server/core/logging.py:32-41]** Uvicorn's `uvicorn` and `uvicorn.access` loggers keep their own plain-text handlers with `propagate=False`. Production logs therefore mix formats, log each request twice, and include full query strings (NFR-OPS-01). **Fix:** clear those loggers' handlers and set `propagate=True` in `configure_logging`, or document `--no-access-log --log-config` in the launch command.
- **[shared/src/dropshare_shared/schemas/envelope.py:9-38, schemas/health.py:14,20]** `extra="forbid"` on response models means an installed client fails to parse any response that gains a field. Every additive server change would become a breaking change, against FR-UPD-04's versioning assumption. Conventions §5 requires `forbid` only on request models. **Fix:** use the default (`ignore`) on response and envelope models.
- **[shared/src/dropshare_shared/schemas/envelope.py:32]** `ErrorBody.code: ErrorCode` is a closed enum. A client built before a new code exists can't parse that error at all. **Fix:** parse unknown codes leniently on the client (for example `ErrorCode | str`), falling back to HTTP status plus `message`.
- **[shared/src/dropshare_shared/naming.py:14-20]** `NameProblem` uses English sentences as enum values. Once these go on the wire (validation `details`, "Can't sync" reasons), rewording a message breaks the contract. **Fix:** stable values (`EMPTY`, `TOO_LONG`, …) plus a separate message mapping.
- **[shared/src/dropshare_shared/naming.py:34]** Length is counted in code points. Verified: 255 emoji (510 UTF-16 units) pass, but NTFS can't create that name. Lone surrogates such as `"\ud800"` are also accepted (verified) and would fail to encode later, giving a 500. **Fix:** measure `len(nfc.encode("utf-16-le")) // 2`; reject names that fail `encode("utf-8")` with a new `NameProblem`; add tests.
- **[server/src/dropshare_server/storage/local.py:10]** `mkdir(parents=True, exist_ok=True)` at startup silently creates a local directory if a NAS or SAN mount is missing. Readiness then reports OK and blobs land on the wrong disk. **Fix:** require the root to exist and refuse to start otherwise (NFR-OPS-03); create it in dev setup instead.
- **[client/src/dropshare_client/ui/main_window.py:10]** `setAccessibleName("App name")` makes screen readers say "App name" instead of the visible "StateLife DropShare" (NFR-UX-02). **Fix:** remove it; a label's accessible name defaults to its text.
- **[client/src/dropshare_client/app.py:51-53]** Logging setup runs before the excepthooks are installed and can raise: `RuntimeError` if `LOCALAPPDATA` is missing, `OSError` from mkdir or opening the file. A windowed PyInstaller build has no console, so on Windows the app would fail to start without any trace. **Fix:** install the hooks first; catch `(OSError, RuntimeError)` and fall back to a stderr handler.
- **[.claude/skills/api-endpoint/references/conventions.md §1]** The new `SERVICE_UNAVAILABLE` (503) and the existing `METHOD_NOT_ALLOWED` (405) are missing from the status-code table. **Fix:** add both rows (a docs edit, needs approval).
