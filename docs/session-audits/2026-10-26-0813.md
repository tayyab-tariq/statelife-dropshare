## Decisions to confirm (approved in the plan, flagged again by reviewers)

- **D1. Lockout reveals that an account exists** (security and contract reviewers). After 5 bad passwords a real account answers 423 while an unknown name keeps answering 401. Anyone can also lock a known user out for 15 minutes. The plan accepted this. Options:
  - (a) record it in requirements §15 as accepted; or
  - (b) keep a short-lived failure counter for unknown logins too, so they also get 423.
- **D2. Strict refresh-token reuse** (code and contract reviewers). If the response to a refresh is lost and the client retries with the old token, the session is revoked and the user must sign in again. The plan chose no grace window. Options:
  - (a) keep it strict and require the M4 client to never resend a used refresh token; or
  - (b) a 30–60 s grace window in which re-presenting the just-rotated token returns 401 without revoking, provided its successor hasn't been used yet.

### Should fix

- **S1 [server/src/dropshare_server/services/auth.py:137-158] Lockout can be bypassed with parallel requests** (code + security). `locked_until` is checked without a row lock before the slow Argon2 verify; the failure count and lock are written afterwards. Effect:
  - Parallel guesses (up to the threadpool size, ~40) all pass the check, giving about 40 guesses per window instead of 5.
  - Extra failures past the threshold re-lock the account and write more `AUTH_LOCKED` events.

  **Fix:** before verifying, reserve the attempt atomically (`UPDATE … SET failed_login_count = failed_login_count + 1 WHERE id = :id AND (locked_until IS NULL OR locked_until <= :now)`), refuse when no row updates or the count passes the threshold, lock only when the count reaches it exactly, and reset the count on success. Add a concurrency test.
- **S2 [services/auth.py:332-343] Password change bypasses the lockout** (contract + security). A wrong `current_password` on `POST /me/password` doesn't count as a failure. Someone holding a stolen access token can guess the password without limit and then take over the account. **Fix:** count these failures with the same mechanism and return 423 while locked.
- **S3 [dependencies/client_version.py:33-34, core/config.py] Version check fails open** (code + contract). The settings pattern accepts `123456.0.0`, the parser (1–5 digits per part) returns `None`, and the check is silently skipped. **Fix:**
  - Move the header name, version pattern and `parse_version` to `shared/`.
  - Validate `MIN_CLIENT_VERSION` with the same parser at startup.
  - Drop the `is not None` branch.
  - Decide whether pre-release versions (`1.4.0-beta.1`) are allowed; for now they're rejected.
- **S4 [services/users.py:130-131] Unlock by password reset isn't audited** (code + security). `reset-password` clears an active lock but only records the reset (FR-AUTH-06). **Fix:** also record `AUTH_UNLOCKED` with `{"reason": "password_reset"}` when a lock was active.
- **S5 [cli.py:81-92, 178-183] Not every CLI action is audited** (code + security + own trace). `users list` writes no event, and failed actions (unknown user, duplicate, invalid input) vanish with the rolled-back transaction. FR-ADMIN-01 says every CLI action is audited. **Fix:**
  - Record list operations, adding a `USER_LISTED` action.
  - In `main`'s error branch, record a failure event in its own transaction with the command and error code.
- **S6 [cli.py:172-185] Raw tracebacks on database errors** (code). A wrong host, password or service name, or a schema problem, raises `SQLAlchemyError` with a traceback. FR-ADMIN-01 wants a clear refusal. A race between two admins creating the same username surfaces as an `IntegrityError`, and `--quota-gb nan` or `inf` crashes. **Fix:**
  - Catch `SQLAlchemyError` and print a short message.
  - Map `IntegrityError` on `uq_users_*` to "already taken".
  - Reject non-finite quotas.
- **S7 [cli.py:99-112] Export file handling** (code + security). The CSV is created inside the transaction. If the database fails mid-export, a partial file stays behind with no audit event, and a re-run fails with "already exists". The file is also created with default permissions (usually 0644) on a shared server. **Fix:** write to a temp file created with mode 0600 and move it into place only after the commit (still never overwriting); delete it on failure.
- **S8 [services/auth.py:129] A typed password can end up in the audit log** (security). For unknown users the raw attempted login is stored in `actor_label`, and users regularly type their password into the username field (FR-AUDIT-02). **Fix:** store the attempted login only if it looks like a username or email; otherwise store a placeholder.
- **S9 [services/auth.py:147-153, client_version.py:39] Machine-readable lock and upgrade details** (contract). The lock duration appears only in English text, and 426 `details` is an untyped dict. M4 needs both to show a countdown and the required version. **Fix:**
  - Add `AccountLockedDetails(locked_until, retry_after_seconds)` and `UpgradeRequiredDetails(min_version)` to `shared/`.
  - Send a `Retry-After` header on 423.
- **S10 [services/auth.py:332-347] Change-password errors come in three shapes** (contract). A wrong current password is 403 with no details, "same as current" is 400 with no details, and length errors are a `{loc,msg,type}` list. **Fix:** use 400 `VALIDATION_ERROR` with `{loc,msg,type}` naming the field in every case. 423 remains for lockout once S2 lands.
- **S11 [.claude/skills/api-endpoint/references/conventions.md §1] Missing 403 codes in the conventions table** (contract). `ACCOUNT_DISABLED` and `PASSWORD_CHANGE_REQUIRED` aren't listed. Both share 403 with `FORBIDDEN`, so clients must branch on `code`. **Fix:** add the rows and that note. This is a docs edit and needs approval.

### Nits

- `services/auth.py:51`: every 401 has the same code and message. Add `details.reason` (`token_expired`, `session_revoked`, `refresh_reused`, …) so M4 can tell users why they were signed out. Additive.
- `core/error_handlers.py:47`: every 401, including requests with no credentials at all and routine token expiry, writes an `access.denied` row in its own transaction. Consider skipping requests with no credentials and plain expiry to limit audit flooding from the internet.
- `core/error_handlers.py:12-14`: `core/` now imports `dependencies/` and `services/`. Move the denied-audit hook up a layer.
- `api/v1/__init__.py:8`: the version check covers the whole `/api/v1` router. The release endpoints (F7) must be exempt, or an outdated client can't download its update.
- `services/auth.py:115-198`: `login` is about 85 lines; split it. `_target(user)` is duplicated in `auth.py` and `users.py`.
- `core/security.py`: the `pwc` claim is encoded but never read. Drop it or comment why.
- `services/auth.py:154`: unlock-on-expiry is recorded lazily, at the next sign-in attempt. Document it.
- `services/users.py:68`: `casefold()` can make a 320-character email longer than the column. Check the normalized length.
- `services/users.py:138`: disabling an already-disabled user still bumps the token version and writes an event.
- `services/auth.py`: small timing difference between unknown and known users (different amounts of DB work after Argon2).
- `schemas/auth.py:16-17`: `device_name` and `device_os` accept whitespace-only strings. `token_type` could be `Literal["bearer"]`. Add `device_id` to `TokenPairOut` when F5 needs it.
- `api/v1/me.py:15`: `GET /me` is blocked during a forced password change; state that in the M4 plan or allow it.
- `api/v1/auth.py:30`: logout needs a valid access token. M4 should treat a 401 on logout as already signed out.
- Deployment: run uvicorn with `--no-proxy-headers` so `TRUSTED_PROXIES` is the only place that decides which proxies to trust. Track the audit-table grant (FR-AUDIT-03) as a deployment blocker.
