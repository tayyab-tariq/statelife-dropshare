## Findings

### Blockers

- **B1 [platform/windows/recycle_bin.py:16,42-51]** `FOF_WANTNUKEWARNING` doesn't fail safely, despite the comment.
  - Windows shows a "permanently delete?" prompt when an item can't be recycled: a folder too big for the bin, or a bin turned off for that drive.
  - Without that flag, `FOF_NOCONFIRMATION` deletes permanently and silently.
  - Either way, sign-out with "Move the files to the Recycle Bin" can destroy files. The prompt comes from a pool thread with no owner window.
  - The `windows_only` test only checks that the source is gone, so it can't tell recycling from deletion.
  - Fix: decision D1. (code, security, ui)
- **B2 [services/auth.py:57-59,84; controllers/session_controller.py:179-182]** A password longer than 128 characters (login or current password), or a login over 320, makes the shared model raise `ValidationError`.
  - Its text includes `input_value='S3cretPassw0rd-…'` (reproduced), and it is logged with `exc_info`.
  - `RedactSecrets` only cleans the log message, not tracebacks.
  - Fix:
    - check max lengths in the controller
    - catch `ValidationError` without logging the input
    - set `hide_input_in_errors` on the shared auth request models
    - redact in a `Formatter` so tracebacks are cleaned too
  - (contract, security)
- **B3 [ui/forms.py:11, ui/stateful_view.py:30-54, ui/main_window.py:21]** Labels get a fixed `setAccessibleName`, which replaces their text for screen readers. Narrator says "Sign-in message" or "Error" instead of the message itself, and "Signed-in account" instead of "Alice (alice)".
  - Fix:
    - Leave message labels unnamed, so their text is what's read.
    - Find them in tests by `objectName`.
    - Set value names like "Signed in as: Alice (alice)" whenever the value changes.
    - Raise an accessibility Alert when a message appears.
  - (ui)
- **B4 [services/sync_folder.py:19-47 + controllers/session_controller.py:144-154]** The sync-folder check accepts the home folder, drive roots, known shell folders, the app-data folder, and parents of OneDrive or Dropbox. `_is_inside` only checks one direction.
  - Sign-out "remove" then moves the whole root. Choosing `C:\Users\alice` would put the whole profile in the Recycle Bin, and OneDrive would sync those removals to the cloud.
  - Fix: decision D2. (code, security)
- **B5 [services/api_client.py:169-172; services/tokens.py:35-43]** Two paths send a used refresh token again (OQ-16), which revokes the session family and writes a false reuse audit event:
  - A refresh that gets a 5xx or a body that isn't the error envelope (for example a proxy 502 or 504 after the server already rotated the token) keeps the old token.
  - A failed credential-store write after a rotation leaves the used token stored, and the next launch sends it.
  - Fix:
    - clear the tokens on any refresh answer except 400, 426 and 429
    - delete the stored token before sending a refresh
    - on a failed `set`, try to delete the stored token
  - (security, contract)
- **B6 [controllers/session_controller.py; ui/change_password_dialog.py:80-82; ui/app_shell.py:126-129]** Session operations aren't serialised, and the reject button stays enabled while busy.
  - Escape or "Sign out" during a pending forced change runs `sign_out` alongside `change_password`.
  - The late change-password response then calls `tokens.store` after the clear, writing a refresh token back. The next launch resumes a session the user signed out of.
  - Fix: one session operation at a time in the controller; disable the reject button and ignore Escape while busy. (code, ui)

### Should fix

- **S1 [services/auth.py:95-109]** `sign_out` doesn't catch `UpgradeRequiredError`. The server returns 426 before auth, so on an out-of-date client the step that moves the files is skipped and `sync_root` stays set. Treat it like `OfflineError`.
- **S2 [services/auth.py:85-87]** `change_password` reports failure if `/me` fails after the password has already changed. A retry then fails with "current password is incorrect". Count it as a success once the new tokens are stored.
- **S3 [ui/sign_in_dialog.py; ui/app_shell.py:69]** Cancel or Escape during a pending sign-in sets the tray to "Signed out", but the late success still opens the main window. Disable Cancel while busy.
- **S4 [ui/app_shell.py]** Dialog lifetimes and routing:
  - The password, folder and sign-out dialogs are never deleted, and stay connected to controller signals.
  - `_signed_out` leaves voluntary dialogs open.
  - `open_app` opens the sign-in dialog over an open password dialog.
  - `_background` is never cleared, so after an autostart and a later sign-in, no window appears.
- **S5 [ui/main_window.py:89-95]** The empty and error states replace the page holding "Sign out…" and "Change password…". A user who cancels the folder chooser can't sign out. Keep the account actions outside `StatefulView`.
- **S6 [ui/sign_in_dialog.py:37,68]** The server field is used even when "Use a different server" is unchecked. A saved override also shows as unchecked and hidden.
- **S7 [app.py:147-151; ui/app_shell.py:90-93]** Quit doesn't wait for work in flight: `api.close()` can run under a worker, and the pool can block exit. Stop new work, then `QThreadPool.globalInstance().waitForDone(timeout)`, then close (architecture.md §2).
- **S8 [single_instance.py; ui/main_window.py:100-103]** FR-CLIENT-07 on Windows:
  - `removeServer` does nothing there, and two `listen` calls on one name may both succeed. Add a `QLockFile` or a named mutex.
  - `bring_to_front` doesn't restore a minimised window.
  - Windows' foreground lock may only flash the taskbar button; call `AllowSetForegroundWindow` from the second instance.
  - Needs a Windows check.
- **S9 [ui/tray.py; app.py:122]** No `QSystemTrayIcon.isSystemTrayAvailable()` check. Without a tray, closing the window hides an app that can't then be quit.
- **S10 [ui/theme.py; ui/app_shell.py:193-195; ui/tray.py]** Tray state is shown by a colour dot only:
  - Paused and Signed out share a grey.
  - High contrast makes all states the same colour.
  - The icon isn't redrawn when the theme changes.
  - Pause is stored as the tray state, so Resume shows "Up to date" even while offline.
  - Fix: a glyph per state, a separate `paused` flag, and a redraw on scheme or palette change.
- **S11 [ui/sign_out_dialog.py:24-27; ui/app_shell.py:181-185]** The folder that will be moved appears only in the accessible description, not on screen. Sign-out shows no progress and can be started twice.
- **S12 [controllers/sync_folder_controller.py:49,66; controllers/messages.py:42-43]** Raw exception text reaches the user (`[WinError 5] …`), and every `OSError` is reported as a credential-store problem. Map file-system errors to their own messages.
- **S13 [services/api_client.py:151-172,184-202]** Refresh requests skip `_send`, so they aren't logged and lose the request ID. Non-envelope errors from a proxy, such as 429 or 502–504, become "INVALID_RESPONSE". Fall back on the HTTP status.
- **S14 [shared/schemas/users.py:30]** `UserOut.role` is a strict enum. A new role would break every installed client's `/me`. Make it tolerant like the M3 response enums (FR-UPD-04).
- **S15 [controllers/worker.py:44-60]** Suspected: each `_Signals` object may leak through Qt-held closures, or be destroyed on a pool thread. Verify with a weakref check; `deleteLater()` in the callbacks.
- **S16 [client/tests/client_fakes.py; client/tests/test_api_client.py:183-191]** The fake server differs from the real one, so some tests can't fail where the real server would:
  - The test for a 403 on refresh: the real refresh never returns 403, so "account disabled" never appears that way.
  - The fake doesn't require `X-Client-Version`.
  - Its logout leaves access tokens valid.
  - It has no lockout, no `password_reused` error, no case-insensitive email login, and no handling of a disabled account on refresh.

## Decisions needed

- **D1 (B1) Recycle Bin on Windows:**
  - **(a)** Use `IFileOperation` through `ctypes`/COM (no new dependency) with a progress sink. Its `PreDeleteItem` checks `TSF_DELETE_RECYCLE_IF_POSSIBLE` and aborts any item that would be deleted permanently, so files are recycled or left alone, never destroyed. This is the most robust option, but it's more Windows-only code to check on the Windows machine.
  - **(b)** Keep `SHFileOperation`, but on sign-out "remove" rename the folder aside ("StateLife DropShare (signed out 2026-10-27)") instead of recycling. No deletion at all, but the files stay on disk.
- **D2 (B4) Allowed sync folders:**
  - **(a)** Refuse drive roots, the home folder and its ancestors, known shell folders (Desktop, Documents, Downloads…), the app-data folder, and any folder that contains another sync tool's folder. Accept other existing folders.
  - **(b)** Everything in (a), and also require a new or empty folder.

Recommendation: D1 (a), D2 (b). Together they make sign-out "remove" safe: only an empty-at-start DropShare folder can ever be recycled, and recycling can't become permanent deletion.
