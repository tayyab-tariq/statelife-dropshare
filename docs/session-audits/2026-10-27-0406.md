## Findings

### Blockers

- **B1 [client/src/dropshare_client/sync/scanner.py:76-83]**
  - **Problem:** `scan(key)` for a folder key calls `_visit()` and ignores its "look inside" result, so the folder's contents are never scanned. `SyncCore.cycle` still loads the base and remote subtree, so every synced child reads as "deleted here".
  - **Consequence:** `DELETE_REMOTE` sends them to the server trash, and other devices then recycle their copies.
  - **Reachable in normal use:** the device's own download of a new remote folder fires watcher events that collapse to the folder key. A case-only folder rename, a remote trash of a folder (FR-CONF-03 local additions recycled), and a folder copied into the sync root also reach it.
  - `_expect_folder_unchanged` (executor.py:320-334) uses the same scan, so its safety check is empty.
  - Found by code-reviewer and sync-reviewer.
  - **Fix:** `if self._visit(path, info, result): self._walk(path, result)`; add tests that run cycles on folder and file keys (see S22).
- **B2 [client/src/dropshare_client/ui/app_shell.py:305-316, also :234-239]**
  - **Problem:** `_confirm_deletes` closes the previous mass-delete dialog with `done(Accepted)` before replacing `self.delete_dialog`. `finished` fires synchronously and `_deletes_answered` calls `answer_deletes(True)`, which approves the *new* pending deletes unseen.
  - **Reachable:** with the dialog open, choose Pause then Resume from the tray. `_close_dialogs` has the same pattern.
  - **Consequence:** FR-SYNC-08 bypassed.
  - Found by UI, code and sync reviewers.
  - **Fix:** detach first (`old, self.delete_dialog = self.delete_dialog, None`), close with `Rejected`, and never close a pending question as Accepted; add a test for "asked again while open".
- **B3 [client/src/dropshare_client/sync/remote_tree.py:35-65; executor.py:121-124, :192, :198; scanner.py:62-63]**
  - **Problem:** names from the server are never validated on the client (windows-fs.md requires `dropshare_shared.naming`), and no disk path is checked to stay inside the sync root.
  - **Consequence:** on Windows, a name like `..\AppData\...\Startup\x.exe`, `C:\...`, a UNC path or `a:b` is one "segment" for `/`-splitting. A compromised server or injected journal row can then write files outside the root; UNC also leaks NTLM credentials. The `.part` name likewise uses an unvalidated `content_hash`.
  - Found by security-reviewer; confirmed independently.
  - **Fix:** run `validate_name` in `from_node`/`_from_change` (drop and list as a problem); add a containment check in `Scanner.disk_path`; check `content_hash` is 64 hex characters or name the `.part` file by node ID only; add `windows_only` tests with backslash, drive and UNC names.
- **B4 [client/src/dropshare_client/controllers/sync_controller.py:155-164, :219-225; session_controller.py:161-175; store/index.py:217-222]**
  - **Problem:** a missing binding counts as "not another account". It goes missing while the previous account's files remain:
    - sign-out with "remove files" destroys the index *before* recycling the folder, and the recycle can fail (a file open in Word, or `unsafe_to_remove`), leaving `sync_root` set;
    - a schema rebuild drops `meta`.
  - **Consequence:** user B then signs in and every one of A's files is uploaded into B's account.
  - Found by security-reviewer and sync-reviewer.
  - **Fix:** see decision D3.
- **B5 [client/src/dropshare_client/sync/core.py:149-156]**
  - **Problem:** on `UnknownChangeError`, `fetch` resets to cursor 0 and replays the same journal, which still contains the unknown row. That is an unstoppable tight loop against the server.
  - **Consequence:** it hits every installed client as soon as a newer server adds a change type (F1 moves, F3 restore).
  - Found by contract, code and sync reviewers.
  - **Fix:** refetch only that node (`GET /nodes/{id}`: upsert on 200, remove on 404), advance past the change, and update the shared `ChangeOut` docstring.
- **B6 [client/src/dropshare_client/sync/paths.py:96-103]**
  - **Problem:** `conflict_name` loops forever when the label alone can't fit in 255 UTF-16 units (a long display name or a long post-dot "extension"), or when the display name contains DEL (0x7F).
  - **Consequence:** the engine thread hangs with no stop check.
  - Found by code-reviewer.
  - **Fix:** truncate `who` and the extension so the tail always fits; sanitise with the shared naming rule; bound the loop; add tests.

### Should fix

- **S1 [server/src/dropshare_server/services/uploads.py:275-289; sync/executor.py:354-362; sync/remote_tree.py:111-115; sync/core.py:148-163]**
  - **Problem:** replaying a completed upload returns the node even after another device trashed it. `_remember` puts it back in the tree and writes a base entry, so it shows "up to date" while the file is only in the server trash, and later edits retry forever.
  - A failed `save_remote` mid-fetch also leaves the in-memory tree ahead of the index.
  - **Fix:**
    - `_replay` signals "trashed" (the client then uploads as a new file);
    - add revision tombstones in `RemoteTree`;
    - reload the tree from the index when a fetch fails;
    - after N replans, check the key with `get_node`.
- **S2 [sync/engine.py:301-305; sync/core.py:169-200; services/files.py:134]**
  - **Problem:** journal recovery runs only once, after the first fetch, and is skipped entirely if that fetch fails. A lost `complete` followed by an offline edit then becomes a conflict against the user's own upload.
  - `complete` uses the default 60 s read timeout, while the server hashes up to 10 GiB in that request. Large uploads time out and show "Offline".
  - **Fix:** recover after every successful fetch; give `complete` a long timeout.
- **S3 [services/files.py:43-50, :134-140, :206; sync/core.py:330]**
  - **Problem:** `UPLOAD_INCOMPLETE` and a third `CHUNK_HASH_MISMATCH` become permanent "can't sync" problems instead of being retried. `QUOTA_EXCEEDED` and `FILE_TOO_LARGE` at complete leave the session holding quota for 24 h.
  - **Fix:** resend the missing chunks on `UPLOAD_INCOMPLETE`; back off on these codes; add the quota codes to `_UPLOAD_OVER`.
- **S4 [sync/executor.py:262-265; server/src/dropshare_server/services/nodes.py:177-183]**
  - **Problem:** a folder trash checks only the folder's own revision. A child another device adds between this client's fetch and its delete goes to the trash with the folder, and that device then recycles its copy. Nothing is lost (server trash), but this breaks FR-CONF-03.
  - **Fix:** needs a server contract change (see D2).
- **S5 [sync/scanner.py:130-153]**
  - **Problem:** two on-disk names with one key (NFC and NFD, or `ß` and `ss` under casefold) in the same folder. The last one listed silently wins: one replaces the other's content on every device, and the other is never synced or listed.
  - **Fix:** detect duplicate keys, defer both, and record a problem.
- **S6 [sync/scanner.py:85-100]**
  - **Problem:** `resolve()` follows links and junctions in *parent* segments. On a folder-scoped cycle, a synced folder replaced by a junction lets downloads and recycles act outside the root. Links are only checked on full scans.
  - **Fix:** check each parent segment with `lstat` and `is_junction`.
- **S7 [sync/scanner.py:113-119]**
  - **Problem:** a file vanishing between `scandir` and `entry.stat()` raises `FileNotFoundError` inside the folder-level `try`. The whole folder listing is dropped and its children read as deleted. This is a macOS dev-layer issue only: on Windows `DirEntry.stat` uses cached data.
  - **Fix:** stat each entry in its own `try`.
- **S8 [controllers/sync_controller.py:143, :174-179]**
  - **Problem:** pause or resume while the engine is starting is lost. The UI says Paused while the engine syncs, or the reverse.
  - **Fix:** in `_started`, apply the current `_paused`.
- **S9 [controllers/sync_controller.py:216-245; app.py]**
  - **Problems:**
    - `running` turns False before the old engine has stopped, so a quick re-sign-in opens a second `Index` on the same file;
    - when `stop()` times out, the index is still closed or destroyed under the live thread;
    - `shutdown()` ignores an engine that is still starting.
  - **Fix:** add a "stopping" state that `start()` queues behind; don't close or destroy on timeout; in `shutdown`, wait for the pool, then stop whatever engine started.
- **S10 [controllers/sync_controller.py:78-129; ui/app_shell.py:293-303]**
  - **Problem:** one `_Relay` is shared by all engines, so late reports from a stopping engine count as current. After sign-out they can open the mass-delete dialog or flip the tray. `NEEDS_CONFIRMATION` and `UPGRADE_REQUIRED` aren't gated on `_user`.
  - **Fix:** a relay per engine (or a generation counter), plus gating on `_user`.
- **S11 [ui/mass_delete_dialog.py:20-23]**
  - **Problem:** on Windows the button box puts "Delete files" first; with auto-default focus, Enter may delete.
  - **Fix:** `pause.setFocus()` and `delete.setAutoDefault(False)`; add a test that presses Return.
- **S12 [ui/app_shell.py:112-123, :305-313]**
  - **Problem:** the mass-delete question is easy to miss while the app runs in the tray. `open_app` doesn't bring `delete_dialog` forward, and there is no tray notification.
  - **Fix:** include it in `open_app`; notify when asking.
- **S13 [ui/app_shell.py:259-263]**
  - **Problem:** after `folder_rejected`, the tray stays "Syncing" and the window still shows the rejected folder.
  - **Fix:** set Paused with "no sync folder chosen", and call `_show_account()` after `cleared`.
- **S14 [ui/app_shell.py:218-223]**
  - **Problem:** the result of `session.sign_out()` is ignored after the stop. If the offline retry made the session busy, the user stays signed in with sync stopped (index possibly destroyed) and "Signing out…" shown forever. Sign out also stays enabled during the stop.

### Should fix

- **S1:**
  - **Server:** `_replay` answers `409 REVISION_CONFLICT` (current revision None) if the file was trashed since.
  - **Client:**
    - tombstones in `RemoteTree`;
    - removals are always saved;
    - the tree reloads from the index if a fetch fails;
    - `REVISION_CONFLICT`/`NOT_FOUND` re-checks the node with `get_node`.
  - The M3 test `test_repeated_complete_returns_this_uploads_result_not_later_edits` loses its trash step: that case is now the new conflict test.
- **S2:** journal recovery runs after every fetch. `complete` uses a read timeout of at least 60 s, scaled by file size (20 MiB/s).
- **S3:**
  - `UPLOAD_INCOMPLETE` resends what the server lists, once;
  - transient codes (`UPLOAD_INCOMPLETE`, `CHUNK_HASH_MISMATCH`, `RATE_LIMITED`, 5xx, invalid response) back off instead of becoming problems;
  - `QUOTA_EXCEEDED` and `FILE_TOO_LARGE` cancel the session.
- **S4 / D2:** `DELETE /nodes/{id}?if_cursor=` (optional; shared `NodeDeleteQuery`, `change_repository.any_after` in batches of 1000 for Oracle). The client sends its cursor. Server tests cover refusal and ignoring unrelated changes; client and end-to-end tests cover the race.
- **S5:** duplicate keys in one folder are both refused and listed (scanner unit test; the file-level test skips on APFS).
- **S6:** `resolve()` refuses link or junction parents and ambiguous segments (`UnsafePathError`); `test_a_folder_replaced_by_a_link_is_never_written_through`.
- **S7:** each entry is stat'ed in its own `try`.
- **S8:** the current pause state is applied when the engine has started (`test_pausing_while_syncing_starts_is_kept`).
- **S9:**
  - the controller has a starting/running/stopping lifecycle, and a start during a stop waits;
  - the index isn't destroyed if the engine didn't stop in time;
  - the engine closes its own index;
  - `shutdown()` waits for the pool and also stops an engine that was still starting.
- **S10:** one relay per engine plus a generation counter; the shell ignores sync reports while signed out.
- **S11:** "Delete files" is not auto-default and has no mnemonic; Pause gets focus (`test_return_pauses_instead_of_deleting`).
- **S12:** `open_app` brings the delete dialog forward, and the question is announced in the tray when the app isn't visible.
- **S13:** a rejected folder shows Paused ("no sync folder chosen"); the account view refreshes once it is cleared.
- **S14:** sign-out stops the offline retry, disables account actions, and retries if the session is busy.
- **S15:** a start failure shows the error view with Try again (`test_a_failed_start_offers_to_try_again`).
- **S16:** conflicts are gathered for 3 s into one notification. Without a tray they show in the window status. The main window has a Pause/Resume button.
- **S17:** `RetryLaterError(reason, key=)`; `_required` raises `RuntimeError`.
- **S18:** a malformed `NAME_CONFLICT` detail leads to a retry.
- **S19:** the watcher can restart (a new observer each time); the engine restarts it after a successful cycle, under a lock.
- **S20:** journal rows are begun after the checks, and finished when the step demonstrably didn't happen; "no answer" and crashes keep them.
- **S21:** the controller no longer imports `store/`; the factory in `app.py` does the binding check and passes the index to the engine.
- **S22:** dirty-key mode in the `Device` harness (matrix and new tests); engine test with `watch=True`.
- **S23:** the end-to-end tests now cover:
  - an answer lost on the wire;
  - a repeated trash;
  - a ranged resume;
  - a folder made on both computers;
  - the folder-delete race against the real cursor check.
- **S24 / D4:** `platform.max_path_length()` (259 on Windows, folders 12 shorter). Over-long paths, local or remote, are "can't sync" and never deleted.
- **S25:** the engine reports items left; the tray shows "Syncing (n items)".
