### Should fix

- **[server/tests/conftest.py:161-162]** The `cli` fixture now sets `DB_PORT` only when `TEST_DB_PORT` is set. When it isn't, the CLI's `Settings()` falls back to `DB_PORT` from the developer's `server/.env` (via `env_file`), so CLI tests can connect to the dev port rather than the test database's default port. Example: Postgres tests with no `TEST_DB_PORT` while `.env` still has `DB_PORT=1521`. Before this session the port was always set explicitly. Fix: always set `DB_PORT`, falling back to the dialect's default (1521/5432) when the setting is `None`.
- **[.gitignore:38]** `docs/` is git-ignored as a whole (this predates the session), so the D3/§12/OQ-25 edits and the new `docs/postgres-setup.md` won't be committed. `CLAUDE.md`, `database.md` and the CLI error message (`cli.py:282`) all point at `docs/postgres-setup.md`, which won't exist on the Windows machine or for anyone else cloning the repo. Fix: decide whether `docs/` (or at least `requirements.md` and the setup guides) should be tracked. That's the project owner's call.
- **[server/.env.example]** It's modified relative to the base, but not by the assistant, and the audit couldn't read it (permission-denied). Confirm by hand that it has `DB_DIALECT`/`DB_NAME`/`TEST_DB_DIALECT`/`TEST_DB_NAME`, no longer has `DB_SERVICE_NAME`/`TEST_DB_SERVICE_NAME`, and holds placeholders only (no real password such as the local one).
