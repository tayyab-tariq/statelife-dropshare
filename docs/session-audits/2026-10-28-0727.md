## Findings

### Blockers

- **B1 [client/src/dropshare_client/services/importer.py:131-138, 182-194] Cancel or failure can permanently delete the original that Replace moved aside.** If putting an original back fails, `_take_back` only logs it and `run()` then does `shutil.rmtree(aside, ignore_errors=True)`. Reachable on Windows when the new copy is open (the engine hashing it) at Cancel, and on any OS with two sources of the same name and Replace. Breaks OQ-28 and "never delete except through the Recycle Bin". **Fix:** never `rmtree` the aside folder; a failed restore puts the original back under a free name (or the Recycle Bin) and reports it; reject duplicate source names in `plan()`; tests for both cases.
- **B2 [services/local_files.py:87-98] Save a copy into a folder inside the source copies forever.** `copytree` re-lists the growing destination, filling the disk and the sync folder (which then uploads). Also `lexists` then `copy2` can overwrite a file created meanwhile. **Fix:** refuse a destination at or below the source; create files with `"xb"`; remove a partial copy on failure.
- **B3 [controllers/browser_controller.py:182-187, ui/browser_view.py:207] Opening a folder keeps the previous folder's rows on screen.** The controller clears its rows but the model isn't told, and `show_loading` keeps content. Acting on a stale row (Enter, F2, Delete) uses the wrong path; opening a stale folder builds a wrong breadcrumb. **Fix:** emit `loaded` with no rows on a location change; keep content only for `refresh()`.
- **B4 [controllers/upload_controller.py:48, 54, 55] Byte counts go through `Signal(int)`, which wraps past 2³¹.** Reproduced: 3 GiB arrives as −1,073,741,824, so upload progress is wrong for big files. **Fix:** `Signal(object)`; test with a value over 3 GiB.
- **B5 [ui/upload_dialogs.py:67-104] Escape hides the upload progress without cancelling.** `QDialog.reject()` hides it; the copy runs on with no progress and no way to cancel. **Fix:** `reject()` emits `cancel_requested`; show "Cancelling…" while it stops.

### Should fix

- **S1 [importer.py:182-187]** Cancel unlinks whatever is now at a created path: another device's file the engine downloaded there after a conflict, or the user's own edit. **Fix:** record (file ID, size, mtime) when placing; remove through the Recycle Bin only if it still matches; report the rest.
- **S2 [importer.py:172-175]** Replace leaves the path empty between two renames; a scan or crash in that gap reads as a delete (server node trashed, history lost). **Fix:** hard-link the original aside, then `os.replace(temp, target)`: no gap.
- **S3 [importer.py:172, 198-203]** Held originals are named by UUID, so the Recycle Bin shows a nameless item that restores into the hidden folder; a Recycle Bin failure leaves it hidden with only a log line. **Fix:** hold as `aside/<uuid>/<original name>`; report a failure like the executor does.
- **S4 [browser_controller.py:284-292 → local_files.py:53-85]** Actions use the path read when the page loaded; if another device renamed X and made a new item with X's old name, Delete recycles the wrong item. **Fix:** pass the node ID; re-read the entry in the worker; on mismatch, "changed meanwhile, refresh".
- **S5 [ui/browser_view.py:34, ui/upload_dialogs.py:17, ui/transfers_model.py:5, ui/transfers_view.py:24]** UI imports `services.importer` and `sync.transfers` (architecture §1); `BrowserRow.entry` hands a `store` record to the UI. **Fix:** re-export through the controllers; give rows a `local_path`.
- **S6 [upload_controller.py:84-86]** Quota pre-check uses `UserOut` from sign-in and ignores space reserved by unfinished uploads; a negative remainder isn't clamped. **Fix:** fetch `/me` in `plan()`; clamp at 0; consider `reserved_bytes` in `UserOut` later (contract change, needs approval).
- **S7 [importer.py:89, 164]** Names inside a chosen folder are only validated during the copy, so one bad name rolls back gigabytes at the end. **Fix:** validate in the planning walk.
- **S8 [browser_controller.py:240-248]** A folder trashed elsewhere while open loops on 404 with the raw server text. **Fix:** on NOT_FOUND go to the nearest existing parent with "That folder was moved to the trash."
- **S9 [browser_controller.py:175-178, 212-223]** Offset paging can duplicate or skip rows if the folder changes between pages. **Fix:** drop rows whose node ID is already shown.
- **S10 [browser_controller.py:154-157, 199, 230]** Breadcrumb names and local paths are kept from when the folder was opened; a rename above it elsewhere makes every row path stale. **Fix:** on refresh, take local paths from the index by node ID.
- **S11 [client/tests/client_fakes.py:142-152]** The fake's folder listing differs from the server: no page/limit validation, sort without NFC/ID tiebreak, 404 instead of 400 `not_a_folder` for a file, hand-written node JSON.
- **S12 [platform/windows/explorer.py:9]** `explorer.exe` is found by search (current folder first); no `windows_only` test or check item. **Fix:** absolute path from the Windows folder; add a test and a check item.
- **S13 [importer.py:154, 162, 212, 255; local_files.py:104-130]** NTFS junctions aren't treated as links (copies data from outside, can recurse; a merge into a linked folder writes outside); path checks are lexical only; `disk()` allows `.dropshare-tmp` and the root itself. **Fix:** share the scanner's `_is_link`; compare resolved paths; refuse the temp folder and `""`.
- **S14 [ui/browser_model.py:30-31, 105-107]** `file://host/share/...` drops are imported without asking; touching them opens an SMB connection (credential leak). **Fix:** refuse URLs with a host, or confirm first.
- **S15 [store/index.py:210]** The SQLite URI isn't percent-encoded; a `#` or `%` in the profile path makes every row "Not on this computer yet". **Fix:** `path.as_uri()` with `mode=ro`.
- **S16 [ui/main_window.py:196-204, ui/app_shell.py:242-245]** App-level errors switch to Overview; the offline retry pulls the user out of My files every time. A failed refresh replaces a filled list with the error page. **Fix:** switch only when nothing else can work (signed out, first run); keep content with an inline error.
- **S17 [ui/browser_view.py:190, 216-229, 335-336, 343-347, 457-459]** Folder-level keys (Ctrl+Shift+N) are on the table, which is hidden in an empty folder; the empty page says "Drag files here" but doesn't accept drops; "Upload files…" there silently does nothing for a folder not on this computer; drops while busy are silently ignored. **Fix:** folder actions and drops on the view; say why when nothing can happen.
- **S18 [ui/browser_model.py:169-172, ui/transfers_model.py:40-51]** Every refresh (also after each sync round) resets the model: selection and focus jump to row 0; Transfers resets up to 4 times a second. **Fix:** update by node ID / key with row inserts, removals and changes.
- **S19 accessibility [ui/browser_view.py:244-266, 398-400, 465-490; ui/theme.py:326, 338]** Reasons for disabled actions only in tooltips; confirmations not announced; breadcrumb `&` becomes a mnemonic, long paths don't elide, Tab order and focus after navigation are wrong; the sidebar's focus cue is a 1 px colour change.
- **S20 [browser_controller.py:276-295]** `_restate` rebuilds every row on each Transfers tick (GUI thread); a finished download leaves `entry` empty, so actions stay off until the next refresh.
- **S21 [upload_controller.py:88-105]** Planning a large folder shows nothing and can't be cancelled.
- **S22 [local_files.py:24-30; importer.py]** About 15 user messages written in services; they belong in `controllers/messages.py`.
- **S23 [ui/browser_view.py]** About 420 lines mixing toolbar, breadcrumbs, actions and the upload flow. **Fix:** move the upload flow and the breadcrumb bar out.
- **S24 [ui/theme.py:425, 455-460]** Icons pre-rendered at 1.0/1.5/2.0 only (soft at 125%/175%); in high contrast, icons on selected rows aren't tinted for the highlight.
- **S25 [client/tests/test_browser_ui.py:211-225]** "Signing out clears the list" doesn't sign out; several tests use private attributes instead of accessible names.
