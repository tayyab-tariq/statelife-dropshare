## Findings

### Blockers

- **B1 [client/src/dropshare_client/ui/share_dialog.py:141]** Reopening the Share dialog for another item keeps the previous item's member list visible and usable while the new one loads (`show_loading` keeps content by default). An owner can remove or change a member of the wrong item. Fix: clear the list, members and can-manage flag in `open_for` and load without keeping content; keep content only for the reload after a change. Add a test.
- **B2 [client/src/dropshare_client/controllers/browser_controller.py:146-150, 201-213]** A link that opens a shared folder's top level gives one crumb. `current_folder` treats any single crumb as the top of the user's own sync folder, so New folder, uploads and drops there land in the user's own DropShare, not in the shared folder shown. Fix: treat only the personal root as local; build crumbs through the user's mount when they have one, and otherwise mark the location as not on this computer.

### Should fix

- **S1 [ui/share_dialog.py:111, ui/shared_view.py:141]** "Status" as an accessible name hides confirmations from screen readers. Announce them as the browser does.
- **S2 [ui/shared_view.py:110/113]** Alt+L is used by both Leave and Copy link.
- **S3 [ui/share_dialog.py:138, ui/shared_view.py:158]** Remove access and Leave run without confirmation (ui.md §5). For the recipient, the folder goes to their Recycle Bin.
- **S4 [ui/share_dialog.py:67-71]** The search box and role picker have no visible labels (NFR-UX-02).
- **S5 [ui/browser_model.py:29, 189]** "Only you" is wrong inside shared folders and for items the user has shared, and the comment there is stale. Fix now: base the label on whether the item is in a shared namespace. Showing "you shared this" on the owner's own items needs a contract field and is left for later.
- **S6 [sync/executor.py:368-382; sync/mounts.py:106-118]** Read-only marks are left on where the user may edit: a file moved from a view-only into an editable shared folder, and kept files after access ends. Set the mark to match the namespace after moves, and clear it in `_keep`.
- **S7 [sync/core.py:750]** The viewer undo runs on any 403 for these operations. Limit it to view-only namespaces, and list other 403s in Can't sync, to rule out a rename loop. Also walk with the scanner rather than `rglob`, which follows junctions.
- **S8 [controllers/browser_controller.py:203]** A link to a single shared file reports "no access", because its parent folder isn't shared. Open Shared with me instead.
- **S9 [ui/share_dialog.py:113]** Copy link works before the dialog has loaded. For a mount it then copies the user's private mount ID. Enable it only after loading.
- **S10 [server services/sharing.py:90]** `GET /nodes/{id}/members` on a folder inside a shared folder answers 409. The dialog offers a Retry that always fails. Return the shared folder's `SharingOut` instead.
- **S11 [server services/sharing.py:468-496]** Two simultaneous `POST /mounts` for the same folder: the second gets a 500 on `uq_nodes_mount_key`. Map that conflict to "already added" and return the existing mount.
- **S12 [client/tests/client_fakes.py:333-345]** The client test fake doesn't page Shared with me, and adding a folder there isn't idempotent and returns no `mount_namespace_id`, unlike the server. Make it match the server and add a multi-page test.
- **S13 [ui/shared_view.py:229]** Save a copy and Upload a new version show no progress and have no Cancel.
- **S14 [ui/shared_view.py:114]** Shared with me has no F5, no Enter action on a row and no context menu.

### Decisions needed (not fixed; for you)

- **D1 — Moving out of someone else's shared folder.** An editor can move items out into their own DropShare. Ownership and quota then go to them, and the owner has nothing in their trash. File shares on the moved items travel with them, so the original owner can't remove those shares any more. FR-SHARE-01 lets editors move items *inside* the folder; nothing says whether they may move them *out*. Options:
  - **a) Recommended:** only the folder's owner may move items out of it; an editor gets 403 ("copy it instead").
  - **b)** Allow it, and drop file shares on everything moved, logging `share.removed` for each.
  - **c)** Keep it as it is.
- **D2 — Owner deleting their own unshared folder.** On device A this doesn't check the shared folder's own change journal, so an edit from device B that A hasn't seen goes to the trash with the folder (it can be restored from there). The fix needs an optional parameter on `DELETE /nodes/{id}`, a contract change. Alternatively, record it as a known gap.

## What changed (summary)

- **Server:**
  - groups and their CLI commands, and user and group search;
  - sharing folders: each becomes its own namespace with the same IDs, mounted in place for the owner;
  - members, single-file shares, Shared with me, adding and leaving shared folders;
  - one effective-role rule, quota charged to the owner, moves between namespaces, and access ending (directly or through a group) trashing the person's mount.
- **Sync engine:**
  - one tree across the user's own namespace and every shared folder they added;
