## Findings

### Blockers

- **[server/src/dropshare_server/services/devices.py:50]** Revoking another user's device raises a plain `AppError(404)`, so no `ACCESS_DENIED` audit event is written. FR-AUDIT-01 requires authorization failures to be recorded; the error handler audits only 401/403 or `denied=True` (`core/error_handlers.py:48`). Every other ownership check uses `access.not_found(..., denied=True, target=...)` (e.g. `services/uploads.py:155`). **Fix:** keep the plain 404 for an unknown or already revoked device; for `device.user_id != current.user.id` raise `access.not_found("Device", denied=True, target=("device", str(device_id)))`. The client still gets the same 404. Add an assertion to `test_another_users_unknown_or_revoked_device_is_not_found`: one `ACCESS_DENIED` event for Bob's device, none for the unknown ID. *(security-reviewer said Should fix; graded Blocker under this audit's rubric: missing audit event for a required action.)*

### Should fix

**Sync engine**

- **[client/src/dropshare_client/sync/engine.py:277-278]** The first Can't sync report at the top of `_run` is outside the loop's error handling. If that index read fails (disk I/O error, "database is locked" after the busy timeout), the engine thread dies before its first cycle: the state stays "Syncing", nothing retries, and syncing silently stops until restart. **Fix:** make the first report part of the guarded path (e.g. `_problems = None` sentinel reported at the start of the first `_sync`).
- **[client/src/dropshare_client/sync/engine.py:375]** `_report_problems()` runs right after `cycle()` and before the cycle result is used. A failing read discards the result: backoffs are lost, the state shows Error, and a mass-delete confirmation is postponed to the next cycle. Nothing is lost (core withheld the deletes). **Fix:** report after the result is consumed, and log rather than fail the cycle if reporting fails (a `finally` also covers the nit below).

**Keyboard and accessibility (NFR-UX-02)**

- **[client/src/dropshare_client/ui/sync_log_views.py:150, :219]** "&Show in folder" takes Alt+S, the same as the header's "&Sign out…" (`ui/main_window.py:89`), which is visible on the same pages. Qt then cycles focus and triggers neither. **[client/src/dropshare_client/ui/settings_view.py:216]** "Files &transferred at once" takes Alt+T, the same as the devices list's "&Try again" (`ui/stateful_view.py:64`) when that list fails to load. **Fix:** "Show in fol&der" and "Files transferred at &once" (or other free letters).

**Shell and tray**

- **[client/src/dropshare_client/ui/tray.py:33, :36]** "Recent activity" and "Settings" stay enabled when signed out; `_show_page` (`ui/app_shell.py:228`) then only opens the window, so the item seems to do nothing. **Fix:** enable them with `signed_in` in `_refresh`, as Open sync folder and Pause are.
- **[client/src/dropshare_client/ui/app_shell.py:371]** While a move runs or needs attention, Sign out shows `WAIT_FOR_MOVE` only on the Settings page's status line. Sign out is in the header on every page, so from anywhere else the click looks ignored. **Fix:** disable both Sign out buttons while `folder_move.busy or needs_attention`, with an accessible description saying why (or show the message where the user is).
- **[client/src/dropshare_client/ui/app_shell.py:330, :392]** The same six-line per-account reset (folder move, notifications, activity, can't sync, devices, account label) is pasted into `_needs_sign_in` and `_signed_out`. The next per-account controller will be added to one and missed in the other, and leak one account's state into the next. **Fix:** one `_forget_account()` helper called from both.

**Settings page and folder move UI**

- **[client/src/dropshare_client/ui/settings_view.py:274]** "Move…" stays enabled while a move is running, during start-up recovery, and when a move needs attention. A second move hits `RuntimeError` in `FolderMover.move`, which is reported as the same attention error. A dialog opened during start-up recovery is closed unexpectedly by recovery's `moved` signal. **Fix:** disable Move… while `folder_move.busy or needs_attention`, with a description of why.
- **[client/src/dropshare_client/ui/settings_view.py:342, :348, :352; :276-280; ui/app_shell.py:452-456]** The lasting "syncing is paused" warning fails in both directions. Unrelated actions (revoke, export, any status message) clear it until the next visit. It also never clears when start-up recovery succeeds, or at sign-out, so it can tell the next user something is wrong when it isn't. **Fix:** clear transient messages back to `_lasting_error`, not `""`; reset `_lasting_error` on `folder_move.moved` / recovery success and on sign-out.
- **[client/src/dropshare_client/sync/folder_move.py:412, :437; ui/move_folder_dialog.py:85-97]** A cross-drive copy reports progress and checks Cancel only between files. With tens of thousands of small files, every file sends a progress signal to the GUI thread. With one multi-GB file, there is no progress for minutes and Cancel seems ignored, and the dialog gives no sign that the click registered. **Fix:** check `cancel` per chunk in `_copy_checked` (the existing undo already handles it), report bytes within a file, throttle to about 10 updates per second, and show "Cancelling…" with Cancel disabled once pressed.
- **[client/src/dropshare_client/ui/move_folder_dialog.py:71, :77]** The path is checked only on `editingFinished`, and Move stays disabled until the answer arrives. Typing a path and pressing Enter only starts the check, and nothing shows that a check is running. **Fix:** show "Checking…", and go ahead with the move when Enter was pressed while the check was pending.
- **[client/src/dropshare_client/controllers/diagnostics_controller.py:33; ui/settings_view.py:224]** Export diagnostics has no busy state: the button stays enabled and nothing shows while up to 60 MB of logs are zipped, and a double-click starts two exports to the same file. **Fix:** add `busy_changed`, disable the button and show "Exporting…" while it runs (ui.md §6).

**Maintainability**

- **[client/src/dropshare_client/controllers/settings_controller.py:24]** `Notification` duplicates `Notice` (`controllers/notification_controller.py:29`), and both repeat the `NotificationSettings` fields (`services/config.py`). A type added to one but not the others makes `chosen[kind.value]` in the Settings view raise `KeyError`, or lets `_enabled` drift. **Fix:** one enum, and `getattr(settings, notice.value)` instead of the dict in `_enabled`.
- **[client/src/dropshare_client/ui/settings_view.py:112]** `SettingsView.__init__` is about 140 lines and the widget is 363 lines, against the ~50-line function / ~200-line widget guideline (`.claude/agents/code-reviewer.md`). **Fix:** one builder per card, and move `_DevicesModel` into its own module as was done for `sync_log_models.py`.
