### Should fix

- **[docs/requirements.md:820, server/src/dropshare_server/services/users.py:174]** OQ-14 still says the list will be added "once a source/licence is supplied", and none of the decisions listed above are recorded in §15. The `set_quota` docstring cites "M12 Q4", which exists nowhere in the repo. CLAUDE.md §0 and §4.5 require decisions to be recorded. Fix: update OQ-14, add new OQ entries for the decisions above, and cite the new ID in the docstring. This was already planned as step 6.
- **[docs/deploy/nginx.conf.example:22, :33]** Both rate-limit zones are keyed on `$binary_remote_addr`, and the server listens on `[::]:443`. An IPv6 client controls at least a /64, so it can use a fresh address per request and never hit the sign-in limit, which defeats the protection against password spraying across many accounts. Per-account lockout still applies. Fix: key IPv6 on its /64 (a `map` over `$remote_addr`, tested with `nginx -t` and real addresses), or drop the IPv6 listener until that's done. Note the choice in reverse-proxy.md.
- **[docs/deploy/nginx.conf.example:72]** The proxy's own 429 has no `X-Request-ID`, but §9 says every response carries one. Without it, users and IT have no reference to match against the nginx log. Fix: `add_header X-Request-ID $request_id always;` in `@dropshare_rate_limited`. The app generates its own ID and ignores incoming ones, so nothing needs to go upstream.
- **[docs/ via .gitignore:38]** The whole `docs/` folder is gitignored, so `nginx.conf.example` and `reverse-proxy.md` will never be committed, and the comment in `main.py` points to a file that isn't in the repo. That's in line with the project keeping docs local, but the proxy config is a deployment artefact the infra team needs. Fix (your call): move both to a tracked `deploy/` folder at the repo root, or keep them local and accept that.
- **[client/src/dropshare_client/ui/change_password_dialog.py:31-33]** The hint is now about 60 characters and doesn't wrap. Because it spans the whole form row, its width sets the dialog's minimum width, which at 200% scaling or with large text can be wider than a small laptop screen (NFR-UX-02). Fix: `hint.setWordWrap(True)`.
- **[client/src/dropshare_client/ui/change_password_dialog.py:83-90]** Plausible, needs a Windows check. `show_message` raises an accessibility Alert, then focus moves immediately. NVDA and Narrator often cut an Alert short when focus changes, so a screen-reader user may hear the New password field's static hint instead of "too common". The pattern existed before, but focus can now land on New password. Fix: move focus first, then show the message, or put the message in the target field's accessible description while the error is shown. Verify with Narrator.
- **[server/src/dropshare_server/cli.py:457-478 with services/storage_report.py:59]** An `OSError` from `storage.blobs()` (storage unmounted, permission denied) isn't caught in `main`. The admin gets a raw traceback, which may show the storage path, and no failure audit row is written, although FR-ADMIN-01 says every CLI action is audited. Fix: catch `OSError` in `main`, call `_record_failure(..., "STORAGE_UNAVAILABLE")`, and print a short message without the path.

### Nits

- **[session_controller.py:46, change_password_dialog.py:88]** The field travels as a plain string, and `PasswordField(field)` raises `ValueError` on an unknown value, so the `.get(..., self._current)` fallback can never be reached. Use `Signal(str, object)` carrying the enum, or a lookup keyed by string.
- **[change_password_dialog.py:89-90]** After "too common" or "reused", Confirm still holds the refused password. Clear it when the field to fix is New password.
- **[session_controller.py:260-263]** The combined least/most length branch is harder to read than the two plain branches it replaced. Restore those.
- **[test_app_shell.py:182-183]** The mismatch step checks focus but not the message. Assert "The new passwords don't match." as well.
- **[client_fakes.py:590-604]** The fake's top-level `error.message` is "The request is not valid", while the real server uses the issue's own `msg`. The fake also compares with `.casefold()` instead of `normalize_name`. No user-visible difference today.
- **[users.py:177-180]** After `_require` has already raised 404, the `if user is None` branch only covers a user deleted between the two queries. The negative-quota check runs after the lock is taken. Check the input first, and comment or drop the redundant branch.
- **[cli.py:51, :97]** `int(args.quota_gb * _GIB)` is now repeated. Use a helper, or have `_quota_gb` return bytes.
- **[storage_report.py:1-6, :59]** The blob walk runs inside the open DB transaction (a long-open Oracle transaction on a big store). The docstring calls every extra blob a leftover, but an upload in progress writes its blob before its version row. Count blobs before opening the transaction, and say "possibly leftovers".
- **[main.py:78, :94-102]** `get_resources` runs after the last-resort `try` block. If resources were missing, the response would be Starlette's plain 500 instead of the JSON envelope. This is theoretical, since lifespan always runs first.
- **[scripts/dev/build_common_passwords.py:43]** Length is filtered on the raw entry, not the normalised one (`ß` becomes `ss`). The current file passes the length test, so this is theoretical. Filter on `len(normalize_name(...))`.
- **[api_client.py:289]** The client ignores `Retry-After`. Sync's 2 s backoff retries before the proxy's 10 s window ends; the burst headroom makes that harmless.
- **[nginx.conf.example:52]** nginx's own non-429 errors, such as a 413 over the 16 MB body limit, come back as HTML and would be retried forever as `INVALID_RESPONSE`. This can't happen with 8 MiB chunks; the runbook already says to raise the limit together with the chunk size.

## What changed (summary)

- **New admin CLI commands:** `users set-quota` refuses to go below current usage (trash included) and checks under the upload row lock. `storage report` prints quota, usage, % used and trash per user, plus totals of versions and blobs. Both are audited.
- **Common-password check:** changing a password now checks the bundled SecLists list (29,943 entries of 12–128 characters, case-insensitive). The list ships with the server, with a licence file and a regeneration script.
- **HSTS from the app:** sent when a request came over HTTPS directly or via a trusted proxy's `X-Forwarded-Proto`.
- **Client password dialog:** a refused password puts the cursor in the field to fix, and the hint mentions common passwords.
- **Reverse proxy:** a reference nginx config and runbook (in the gitignored `docs/`). TLS 1.2+, one HSTS header, a global flood guard, a strict sign-in limit, and 429s in the JSON error envelope.
